# SnapFrame

小さなアプリのウィンドウを1枚の「お盆」にまとめ、Windows のスナップでひとまとまりとして扱えるようにするツールです。

お盆をスナップすれば、載せたアプリが全部いっしょに動いてリサイズされます。

## 使い方

1. `snapframe.exe` を起動する
2. 左上の **「＋ ウィンドウを追加」** から、載せたいアプリを選ぶ
3. お盆ごと `Win`+`←`/`→` などでスナップする

### ペインの操作

| 操作 | 動作 |
|---|---|
| ペインをクリック | そのアプリにキーボードフォーカスを移す（アプリの中身でもヘッダーでも可） |
| ペイン間の境界をドラッグ | 分割比を変える |
| ヘッダーをドラッグして別のペインで離す | 2つのペインを入れ替える |
| ヘッダー右端の × | そのアプリだけをデスクトップに戻す |
| 「均等に整列」 | 分割比をリセットする |
| 「すべて解放」 | 全部をデスクトップに戻す |

### お盆自体の操作

タイトルバーはありません。上部のツールバーがそのままキャプションを兼ねていて、右端に最小化・最大化・閉じるが並びます。

| 操作 | 動作 |
|---|---|
| ツールバーの空き部分をドラッグ | お盆ごと移動する |
| 同じ場所をダブルクリック | 最大化・元に戻す |
| 四辺・四隅をドラッグ | リサイズする |
| 最大化ボタンにポインタを合わせる | Windows 11 のスナップレイアウトを出す |

ウィンドウ枠自体は残してあるので、リサイズ・スナップ・影・角丸は通常のウィンドウと同じように効きます。

## 挙動のメモ

**並び方**: ペインは追加した順に、なるべく正方形に近くなるよう「列 × 列内の段」に並びます。分割比はピクセルではなく比率で保持しているので、お盆をどうリサイズしても崩れません。

**フォーカス**: 通常のアプリと同じ感覚で動きます。載せたアプリのどこをクリックしてもそのアプリに入力が移り、他のウィンドウから戻ってきたときは最後に使っていたペインに戻ります。フォーカスのあるペインは常にいちばん手前に来ます。ペインは基本的に重なりませんが、自分でサイズを変えるアプリや、ペインより小さくならないアプリを載せるとはみ出して重なることがあり、そのときも手前に出るのはフォーカスを持っているアプリです。

**復元**: アプリをお盆から外すと、載せる前の枠・サイズ・位置がそのまま復元されます。お盆を閉じたときも同じです。

**追従**: 載せたアプリを自分で終了させると、そのペインは自動的に消えます。タイトルの変更も追いかけます。

## ビルド

通常の PowerShell で動きます。rustc が MSVC ツールチェーンを自力で見つけるため、VS の x64 Native Tools コンソールは要りません。

```bash
cargo run
```

```bash
cargo build --release
```

依存は `windows` クレートのみです。リリースビルドは LTO + `codegen-units=1` + `panic=abort` + `strip` で、200 KB 未満の単一 exe になります。

## 動作環境

Windows 11 (10.0.26100) で開発・動作確認しています。

Windows 10 は未検証です。仕組み自体は動くはずですが、角丸・スナップレイアウト・枠線の暗色化は Windows 11 の機能なので、見た目は変わります。

## 制限事項

- **ストアアプリ (UWP) は載せられません。** 電卓・設定などは Windows が `SetParent` を拒否します。選ぶと理由を説明するダイアログが出ます。管理者権限で動いているアプリも同様です。
- **お盆を強制終了させないでください。** Windows は親ウィンドウと一緒に子ウィンドウも破棄するため、タスクマネージャーから kill すると載せていたアプリのウィンドウごと消えます。閉じるボタンで普通に終了すれば全部きちんと戻ります（SnapFrame 自身が panic した場合も、道連れにする前に返却します）。
- 載せたアプリが自前で描いているタイトルバー相当の UI（Windows Terminal のタブ列など）はそのまま残ります。取り除けるのは OS が描く枠だけです。
- レイアウトは保存されません。起動するたびに空のお盆から始まります。
- タスクトレイ常駐やキーボードショートカットはありません。
